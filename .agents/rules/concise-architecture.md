# Concise Architectural Communication

When explaining architecture, dependency injection tokens, component boundaries, or design trade-offs:

1. **Concepts First**: Explain structural responsibilities, contracts, and data flows using concise prose, bullet points, or minimal structural diagrams.
2. **No Unsolicited Code Dumps**: Do not generate multi-line code blocks or full implementation snippets unless the user explicitly asks for code or requests an implementation sample.
3. **High Information Density**: Keep answers compact, direct, and free of conversational filler, patronizing language, or unnecessary repetition.
