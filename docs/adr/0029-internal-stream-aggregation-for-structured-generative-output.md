# 0029. Hybrid Streaming with Deferred Markdown Formatting for Structured Generative Output

Date: 2026-10-15
Status: Accepted
Relates to: [ADR-0028](0028-culinary-guide-two-stage-inference-and-lazy-markdown.md)

## Context

1. **On-Device Latency & Perceived Responsiveness**:
   - On-device generative models (such as Gemini Nano) exhibit perceptible generation latency compared to cloud inference.
   - Buffering entire multi-item discovery payloads or full recipe outputs before displaying anything forces users to wait behind a static spinner, giving the impression that on-device AI is sluggish and defeating the responsiveness goals of hybrid AI.

2. **Markdown Parsing Fragility & Partial Tag Flicker**:
   - When streaming structured JSON payloads containing formatted markdown strings (such as recipe instructions), intermediate chunks emit incomplete, partial markdown fragments (e.g., unclosed bold tags `**ingredient...` or half-finished bullet lists).
   - Passing incomplete fragments through dynamic HTML parsers (`snarkdown`) produces broken DOM markup and causes visual text flickering and layout jitter during generation.

3. **Retry Artifact Masking**:
   - On-device inference constraints (such as candidate output truncation on Gemini Nano) require automatic service-level retry attempts.
   - Retries in `CulinaryGuideService` emit intermediate reset chunks with empty arrays (`foods: []` or `ingredients: []`) to reset streaming accumulators. Exposing raw reset chunks directly to the UI causes rendered cards and chips to abruptly vanish and reappear.

4. **Presentation State Localization (Coding Standard § 3)**:
   - In accordance with repository coding standards, presentation execution flags (`isSearching`, `isLoadingRecipe`) and error messages belong locally in Angular UI components, not in shared services.

5. **Stage 1 Stream Expansion & Collapse Race Conditions**:
   - While Stage 1 Culinary Discovery (`search`) streams dishes progressively, new stream emissions update the discovery dataset and reset active selection state.
   - Expanding a dish accordion item while Stage 1 is actively streaming can trigger premature expansion/collapse race conditions and unexpected state resets on subsequent stream emissions.

6. **Transactional Caching & Failure Recovery**:
   - In [ADR-0028](0028-culinary-guide-two-stage-inference-and-lazy-markdown.md), search operations clear the recipe accordion cache.
   - Clearing the cache eagerly before a search succeeds degrades the user experience if a transient network/inference failure occurs, wiping the user's previously loaded recommendations and cached recipes.

7. **Stream Chunk Parsing Overhead & Fragment Thrashing**:
   - Running `jsonrepair` and `JSON.parse` eagerly on every individual raw stream chunk introduces CPU parsing overhead and produces frequent intermediate parse exceptions before meaningful token boundaries arrive.
   - Yielding on every raw chunk triggers excessive intermediate UI re-renders with partial or identical data.

## Decision

1. **Hybrid Streaming Architecture**:
   - Feature coordinator services (`CulinaryGuideCoordinatorService`) expose streaming `AsyncGenerator` contracts rather than blocking promises.
   - **Stage 1 Discovery (`search`)**: Returns `AsyncGenerator<StreamingCulinaryDiscoveryWithMetadata>`. Streams `foods` and `honorableMentions` progressively as each item is generated by the model.
   - **Stage 2 Recipe Synthesis (`loadRecipe`)**: Returns `AsyncGenerator<CulinaryRecipeDetail>`. Streams `ingredients` progressively with `recipeHtml: ''` while the recipe markdown instructions are being generated.

2. **Stage 1 Discovery Stream Lock for Dish Accordions**:
   - `<app-accordion-item>` triggers inside `<app-culinary-dish-list>` are disabled via `[isDisabled]="isDiscovering()"` while Stage 1 discovery streaming is active.
   - This prevents premature expansion and collapse race conditions during in-flight discovery stream updates.
   - Once Stage 1 completes (`isDiscovering() === false`), accordion items become interactive and remain expandable throughout Stage 2 Recipe Synthesis (`loadRecipe`), ensuring progressive skeleton states (ingredients, recipe instructions, and token analytics) render on demand.

3. **Single-Pass Sanitized HTML Formatting on Completion**:
   - `MarkdownFormatterService` is invoked strictly once per recipe generation on the complete, fully buffered recipe markdown string.
   - Once the final stream chunk is received, the coordinator converts the complete markdown to sanitized HTML, populates `recipeHtml`, caches the result in `#recipeCache`, and yields the final complete `CulinaryRecipeDetail`. This guarantees `snarkdown` and `DOMPurify` only ever receive valid, complete markdown syntax.

4. **Retry Reset Masking in Coordinator**:
   - The coordinator suppresses empty reset chunks emitted by `CulinaryGuideService` during on-device retry recovery if items have already been yielded to the caller. This ensures the UI remains visually stable while retry attempt 2 spins up in the background.

5. **Unified Cache Hit Streaming**:
   - If a requested recipe already exists in `#recipeCache`, `loadRecipe` yields the cached `CulinaryRecipeDetail` immediately in a single emission and finishes, allowing consuming UI components to use a single, uniform `for await` loop regardless of cache status.

6. **Zero-Signal Feature Services & Transactional Cache Invalidation**:
   - The coordinator maintains zero Angular signals. Consuming UI components own all reactive signals (`signal`, `computed`), execution state flags, and local error display states.
   - `#recipeCache` is cleared safely only upon successful completion of a new search query. If a search fails mid-stream, previous cached recipes are preserved.
   - An explicit `clearCache(): void` method is exposed for manual resets and component unmounting.

7. **Stream Chunk Buffering & Resilient JSON Repair (`AiService`)**:
   - `AiService.generateContentStream` accumulates raw stream text and tracks chunk count in batches governed by `STREAM_CHUNK_BUFFER_SIZE = 5` before executing `parseStreamJSONResponse`.
   - The buffer count resets only after a successful JSON parse and yield. If `jsonrepair` throws on chunk $N$, the count is preserved so chunk $N+1$ immediately retries parsing on the next chunk without dropping accumulated text.
   - If the stream completes with fewer than 5 un-yielded chunks in the buffer, intermediate yields are bypassed and trailing chunks are flushed via `await result.response` with complete `inferenceMetadata`.

## Consequences

- **Positive**:
  - Delivers immediate visual feedback (sub-second perceived latency) for on-device Gemini Nano inference by progressively rendering discovery cards and recipe ingredients.
  - Completely eliminates markdown parsing syntax flicker and DOM layout jitter by deferring HTML formatting to full completion.
  - Prevents jarring visual resets during on-device retry recovery by masking empty reset chunks in the coordinator.
  - Eliminates accordion expansion/collapse race conditions during Stage 1 discovery streaming while keeping Stage 2 progressive skeletons interactive.
  - Provides a consistent caller contract with uniform `for await` iteration across live streams and cached hits.
  - Adheres to repository coding standards by keeping feature services signal-free and localizing UI state in components.
  - Preserves previously cached recipes on transient search failures.
  - Reduces JSON repair execution overhead and intermediate UI rendering thrash by throttling partial structured emissions to 5-chunk batches while maintaining perceived responsiveness.
  - Provides fault-tolerant parsing recovery by retrying repair on immediately following chunks upon temporary syntax failures without resetting buffer progress.
  - Eliminates redundant intermediate yields on stream termination by delegating trailing chunk delivery directly to final response resolution.
- **Negative / Trade-offs**:
  - Recipe instructions text does not render token-by-token; instead, instructions show an animated skeleton while ingredients populate, followed by instantaneous complete HTML rendering upon completion.
  - Intermediate structured UI updates emit at 5-chunk intervals rather than single-token increments.
